# SD-WAN Flutter 多端软件设计

日期：2026-05-27

## 背景

当前目录只有一个 Windows BAT 脚本：`宁波市富金园艺灌溉设备有限公司 (以管理员身份运行).bat`。脚本提供“国际网络加速工具”的命令行菜单，核心能力是：

- 开启加速：添加两条持久路由 `0.0.0.0/1` 和 `128.0.0.0/1`，下一跳为 CPE 网关。
- 关闭加速：删除这两条路由。
- DNS 配置：识别活动网卡，设置预设 DNS、恢复 DHCP，或手动输入 DNS。
- 刷新 DNS 缓存：每次路由或 DNS 操作后执行。
- 权限要求：必须用 Windows 管理员权限运行。

目标是把 BAT 脚本产品化为一个 Flutter 多端软件。第一版优先保证 Windows 端真实可用，其它端保留合理能力和后续扩展入口。

## 已确认决策

- 多端范围：全平台规划，但第一版先保证 Windows 可用。
- 默认配置：允许用户修改 CPE 和 DNS；脚本中的值作为初始默认值。
- 配置档：第一版只展示一套配置，内部数据结构预留多个配置档。
- 权限策略：Windows 启动时检测管理员权限，不足时自动弹 UAC 重新以管理员身份启动。
- DNS 绑定策略：默认按 BAT 分开操作；提供设置项“路由操作同步 DNS”。打开后，开启加速时设置预设 DNS，关闭加速时恢复 DNS 自动获取。
- 主界面：采用“仪表盘 + 设置”的正式软件布局。
- 技术路线：Flutter UI + 平台能力层。

## 目标

第一版交付一个可运行的 Flutter 项目，并在 Windows 端替代 BAT 脚本的主要操作：

1. 启动时处理管理员权限。
2. 显示当前加速状态、活动网卡、当前 DNS。
3. 一键开启或关闭加速路由。
4. 配置 CPE 网关、主 DNS、备用 DNS。
5. 独立配置 DNS 或按设置项随加速开关同步配置 DNS。
6. 记录操作日志，失败时给出中文原因和可复制日志。
7. 在 macOS、Web、iOS、Android 上能启动，并展示平台能力限制或预留入口。

## 非目标

第一版不做后台常驻 Agent 服务，不做企业集中管控，不做账号系统，不做远程下发配置，不做 VPN 协议实现。移动端不直接修改系统路由或 DNS，因为系统权限不允许按 BAT 的方式操作。

## 架构

采用四层结构：

1. Flutter UI 层
   - 仪表盘：状态卡片、开启/关闭按钮、配置摘要。
   - 设置页：CPE、DNS、同步 DNS 开关、本地配置保存。
   - 日志页：命令执行记录、错误详情、复制日志。
   - 帮助页：管理员权限说明、平台能力说明、故障排查。

2. 应用服务层
   - 管理配置读写。
   - 校验 IP 和 DNS 格式。
   - 编排开启、关闭、DNS 设置、DNS 恢复、状态刷新流程。
   - 把平台层错误映射为中文提示。

3. 平台能力接口层
   - `readStatus()`
   - `ensureAdminOrRelaunch()`
   - `enableAcceleration(profile)`
   - `disableAcceleration(profile)`
   - `setDns(profile)`
   - `restoreDns()`
   - `flushDns()`

4. 平台实现层
   - Windows：实现真实路由、DNS、UAC 和状态查询。
   - macOS：第一版展示受限说明，后续接 `route` 和 `networksetup`。
   - Web：展示配置、说明和客户端下载，不修改系统网络。
   - iOS/Android：展示状态说明、配置指引和诊断入口，不直接修改系统路由。

## Windows 命令映射

开启加速：

```bat
route add 0.0.0.0/1 <CPE_IP> -p
route add 128.0.0.0/1 <CPE_IP> -p
ipconfig /flushdns
```

关闭加速：

```bat
route delete 0.0.0.0/1
route delete 128.0.0.0/1
ipconfig /flushdns
```

设置 DNS：

```bat
netsh interface ip set dnsserver "<INTERFACE_NAME>" static "<PRIMARY_DNS>" primary
netsh interface ip add dnsserver "<INTERFACE_NAME>" "<SECONDARY_DNS>" index=2
ipconfig /flushdns
```

恢复 DNS 自动获取：

```bat
netsh interface ip set dnsserver "<INTERFACE_NAME>" dhcp
ipconfig /flushdns
```

活动网卡识别以默认路由和本机 IPv4 为依据，第一版可以沿用 BAT 的命令思路，但输出必须转成结构化状态给 Flutter 使用。

## 数据模型

配置文件保存本地用户配置。第一版界面只显示一个配置档，数据结构如下：

```json
{
  "activeProfileId": "default",
  "profiles": [
    {
      "id": "default",
      "name": "默认加速配置",
      "companyName": "宁波市富金园艺灌溉设备有限公司",
      "cpeIp": "192.168.1.140",
      "primaryDns": "223.5.5.5",
      "secondaryDns": "114.114.114.114",
      "syncDnsWithAcceleration": false
    }
  ]
}
```

状态模型包含：

- 是否为管理员权限。
- 当前平台能力。
- 加速路由是否存在。
- 活动网卡名称和 IPv4。
- 当前 DNS 模式和 DNS 列表。
- 最近一次操作结果。

主界面采用仪表盘：

- 加速状态卡：未开启、已开启、部分异常。
- 活动网卡卡：网卡名称、本机 IPv4。
- DNS 状态卡：自动获取、静态 DNS、未知。
- 操作按钮：开启加速、关闭加速、刷新状态。
- 配置摘要：当前 CPE、DNS、同步 DNS 开关。

设置页：

- 公司名称。
- CPE 网关。
- 主 DNS。
- 备用 DNS。
- 路由操作同步 DNS 开关。
- 保存配置。
- 恢复默认值。

日志页：

- 每次操作的时间、动作、命令、退出码、结果。
- 错误详情。
- 复制日志按钮。

- 为什么需要管理员权限。

## 操作流程

启动流程：

1. Flutter 应用启动。
2. Windows 端检查管理员权限。
3. 如果权限不足，自动触发 UAC 重新启动管理员实例。
4. 管理员实例加载配置并读取系统状态。
5. 进入仪表盘。

开启加速：

1. 校验配置中的 CPE 和 DNS。
2. 添加两条持久路由。
3. 刷新 DNS 缓存。
4. 如果同步 DNS 开关开启，设置活动网卡主备 DNS。
5. 重新读取状态并写入日志。

关闭加速：

1. 删除两条加速路由。
2. 刷新 DNS 缓存。
3. 如果同步 DNS 开关开启，恢复活动网卡 DNS 自动获取。
4. 重新读取状态并写入日志。

独立 DNS 设置：

1. 查询活动网卡。
2. 展示当前 DNS 模式和 DNS 列表。
3. 用户选择设置预设 DNS、恢复自动获取，或输入自定义 DNS。
4. 执行后刷新 DNS 缓存并写入日志。

## 错误处理

- 权限不足：自动 UAC；用户取消时进入只读状态并提示需要管理员权限。
- 未找到活动网卡：提示检查网络连接，并展示检测日志。
- IP 或 DNS 格式错误：在设置页就地校验，不允许保存。
- 路由添加失败：展示命令名、退出码和中文解释。
- DNS 设置失败：展示活动网卡名称、命令名、退出码和中文解释。
- 重复开启或关闭：先读取路由状态，允许幂等操作，不把“已存在”或“已删除”直接当成失败。
- 平台不支持：展示该平台的支持范围和 Windows 客户端建议。
